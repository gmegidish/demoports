# P09: part 0000:9778 (618.65 s to 709.65 s): fire, two 3D stars and the credits

## Summary

This is the credits part, rendered as a **fire effect**. Everything is drawn into page 1, which is the fire "fuel" buffer. Each frame a fire filter averages page 1 in place and writes the result to the screen (A000). The part draws these things into page 1:
- a random seed row at y = 199,
- two copies of a flat-shaded **3D pentagram star** (built by 0e5a:1478), which orbit an ellipse and tumble,
- a **wave text** line (the credits, centered at (160, 95)), drawn with the bitmap font 19.pcx / 20.bin.

All of these then burn and rise.

Fire palette: indices 0..80, black -> red -> yellow -> white, built by fireRamp(80). Every other palette entry is 0.

The part has three phases, all timed with the 100 Hz clock:
1. **Fade-in**, 200 ticks: fire only. Palette entries 0..80 fade from -60 to 0.
2. **Main**, 8000 ticks: fire + stars + credits text (8 strings, a new one every 1000 ticks, starting after 500 ticks).
3. **Outro**, until tick 8800 of the same clock: the fire seed fades out per frame, and fire2 is used with a wobbling row offset, which gives slanted flames.

There is **no vertical retrace wait** anywhere in the loops. The frame rate is CPU bound. The text angle (+20 deg/frame) and the outro seed decay (-1/frame) are per frame. In the capture the outro flames die out about 3 s after phase 3 starts, and r2 goes from 200 to 0 one step per frame. That points to roughly 70 fps (GUESS; use 70 Hz).

Checked against the capture (`capframe --sheet 618 710 4` and `--sheet 700.5 709.5 0.75`):
- t = 618: black.
- t = 622: one star (both copies overlap at x = 0) near the bottom, fire at the bottom.
- t = 626 to 630: two stars at the top, then "CREDITS".
- Then CODER: ADEPT, CODER: SKYER, MUSIC: BAHC, MUSIC: PASO, GFX: Mr.ED, GFX: Insane Tilt, about 10 s each. The glyphs are blurred and burning, in fire colours.
- About 701.2: the outro starts. Slanted streaks, fire gone by about 704.5, black until the end.

All of this matches the reading below.

### Fire seed (the same code appears three times; the outro uses variables)
```
seedRow(R1 = 255, R2 = 200, BASE = 55):
  for (x = 0; x <= 319; x++) putPixel(x, 199, Random(R1))
  for (x = 0; x <= 319; x++) {
    if (Random(2) == 1) putPixel(x, 199, 0)
    else { yy = 199 - Random(10); c = Random(R2) + BASE; putPixel(x, yy, c) }   // Random(10) is called BEFORE Random(R2)
  }
```
putPixel writes into the active page, which is page 1 here. It takes the low byte of c. Random call order per frame: 320 x Random(R1), then per x: Random(2) and, if that is not 1, Random(10) then Random(R2). Randomize seeds the generator from the clock, so exact RNG reproduction is not needed.

### Phase 1: fade-in (200 ticks)
```
loop {
  t = elapsed(a394)                      // stored in a3a4 (int32)
  if (PollKey()) break                   // -> goes on to phase 2 setup
  d = Round(f64(t*60) / 200.0f - 60.0f)  // t*60 longint mul; fild; Round = half-even; low 16 bits pushed
  setPaletteOffset(pal, 0, 80, d, d, d)  // computed 3 times, same value. dacWrite clamps to 0..63; the shadow stores the unclamped value
  setActivePage(1)
  seedRow(255, 200, 55)
  fire(cap = 80, dst = getPage(0), buf = getPage(1))   // 179b:01cc: page 1 updated in place, result to the screen
} until (t >= 200)                       // signed int32 compare
```
Note: the palette is never set to exactly d = 0 after the loop. The last value used is from the last frame's t < 200, so for example t = 197 gives Round(-0.9) = -1. Entries 0..80 can stay 1 or 2 steps dark for the rest of the part. A port should reproduce this by using the same d from its last phase-1 frame.

### Phase 2: main (8000 ticks)
```

      a   = Real48(f64(Random(10) + 10) / 10.0f)               // 1.0 .. 1.9
      ang = 0.0 (Real48 zero); amp = 0.0

    scale = Round(f64(tt*1000) / 100.0f) // low 16 bits

    if (tt <= 500) amp = Real48(f64(tt*10) / 500.0f)                  // 0 -> 10
    else           amp = Real48(10.0f - f64((tt-500)*10) / 500.0f)    // 10 -> 0 (and negative after 1000)
    if (tt < 900 && textIdx <= 7)
      font.DrawWave(a = a, b = ang, c = amp, n = scale)   // 0db3:0429, into page 1
  }
  fire(80, getPage(0), getPage(1))       // 179b:01cc

```
DrawWave stack mapping (pushes at 0000:9f29): scale -> [bp+0x1c], amp (local 61a) -> [bp+0x16] = L5's `c`, ang (local 620) -> [bp+0x10] = L5's `b`, a (local 626) -> [bp+0x0a] = L5's `a`. So per glyph i:
```
ph = ang*pi/180 + phase[i]
dy = Round(amp*sin(ph)*cos(ph/a))
dx = Round(amp*cos(ph))
```
The spacing is `scale/1000`, so the letters spread out from 0 to normal spacing in the first 100 ticks of each line. The amplitude ramps 0 -> 10 px -> 0 over 1000 ticks. The line is drawn while tt < 900.

Text schedule, in phase-2 ticks:
- line k (1..7) appears at about 500 + 1000*(k-1) + one frame and is drawn for 900 ticks;
- line 8 ("") starts at about 7500 but is not drawn (textIdx 8 > 7).

Phase 2 starts at about 619.15 + 2.00 = 621.15 s, so CREDITS appears at about 626.2 s.

### Phase 3: outro (until t > 8800; a394 is NOT reset, t keeps counting from phase 2)
```
cap = 100; r1 = 254; r2 = 200; base = 54       // int16 locals
loop {
  t = elapsed(a394)
  if (PollKey()) break                        // -> cleanup
  setActivePage(1)
  seedRow(R1 = r1, R2 = r2, BASE = base)      // BASE is added as int32 (cdq) and the low word is pushed; same result
  fire2(off = cap, cap = 80, dst = getPage(0), buf = getPage(1))   // 179b:021a
  cap = 100 - Round(sin(f64(t) / 200.0f) * 8.0f)   // fild dword [a3a4] directly; int32 sub, low word kept
  if (r1 > 0) r1--; if (r2 > 0) r2--; if (base > 0) base--      // signed, per FRAME
  setActivePage(0)
} while (t <= endT + 800)                     // exits when t > 8800 (int32 compare)
```
Random(0) returns 0 in BP7, so once r1 and r2 reach 0 the seed row is all 0 and the fire dies. With fire2 the neighbour row offset is `off+219..221` = 311..329 for off = 92..108. That is a sheared upward flow: the slanted streaks seen in the capture from about 701.3 to 704 s. The wobble is sin(t/200) with t in ticks (period 12.57 s), so it barely moves during these 8 s.

### Key handling
The three phases each exit to the next one on PollKey(). PollKey returns the sticky flag DS:a3ac (and halts on ESC), and each loop polls before it draws anything, so a key press runs through all three phases at once and goes straight to cleanup. Main then waits for its tick 70965.

### Pixel and screen notes (port)
- Page 1 = linear 320x200 bytes, the fire source. The screen = A000 linear mode 13h.
- fire (179b:01cc) writes the screen only where the averaged value is nonzero, and only for i <= 63360. So screen row 199, row 198 except x = 0, and every "v == 0" pixel keep their previous screen contents. The previous part ends with clearScreen (0000:8195), so they stay black (GUESS that nothing else draws to them).
- The star and the text are never drawn on the screen directly; they appear only through the fire filter. That is why they look blurred and burning.
- No palette writes after phase 1; no vsync; no explicit present (fire writes A000 directly).

Other details:
- **Face colours** from AddTriangle's counter: start +0x80 = 20, step set to 5 before each face. Faces 1..11 get 25, 30, ..., 75. Faces 12..20 get 20, because the face count is > 10, so the colour resets to minColor. With flags = 9, every face is fill type 1 (flat, min/max range) with shading mode 0x08 (flat Lambert), so TFace.Shade overwrites the colour each frame, within 20..80 (L4). The counter values therefore do not matter for the image.
- AddTriangle allocates **new TPixels per triangle**, and AddFace (1342:2c6c) dedups them by position (L4).
- The star has 12 distinct points, no pivot change. ScaleUniform(0.5) is then applied by the part, giving radii 25 / 9.549 and apexes ±5.

**Correction to L5:** 0e5a:1b9f is **not** nested. It is a far procedure called with `push cs; call` and no parent BP, and it ends with `retf 0x10`. Its arguments are p1 [bp+0x12], p2 [bp+0x0e], p3 [bp+0x0a] (far pointers to Vec3 of single, copied locally, 12 bytes each) and mesh [bp+6]. Its body is as L5 describes (SetColorStep(5); NextColor; `if (faces.Count(+0x5f) > 10) +0x80 = +0x7e`; new TFace(+0x92 low byte, +0x7e, +0x7f, +0x80) with VMT 0x23da; 3 x GetMem(0x2c) + TPixel.Init(VMT 0x239a, x, y, z, colour 0); SetVertices(v1, v2, v3, v3); AddFace). 0e5a:13e4 / 1433 are nested (near, `push bp` before the call, `ret 8`), as L5 says.

## Font details used here (L5 covers the unit)

- Glyph source 19.pcx (pixels 0..3 only). After the remaps, glyph pixels are 71, 42, 23 (fire palette). Colour 0 is transparent.
- SetWave(160, 95, s): phase[i] = Real48((1.0f - i/len) * 2*pi).
- DrawWave clips vertically only, against the clip rect 0..199 set by PartInit. There is no horizontal clip, but the strings fit.
- Glyphs blit into the active page (page 1) with stride 320.

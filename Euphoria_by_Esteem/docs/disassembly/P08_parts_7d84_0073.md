# P08: part 0000:7d84 (terrain flight, 554.60 s to 618.65 s), end part 0000:0073 ("THE END", 709.65 s to the end), 1117:20e8, and the final text screen

## Summary

- **0000:7d84 "terrain flyover"**. A 3D landscape is built from a heightmap picture (resource item 33, blurred 5 times). It is a 17 x 31 vertex grid with angle (Phong-table) shading, yellow/brown palette 1..100. The grid scrolls toward the viewer by one heightmap pixel per frame. Behind it, the background picture (item 35, a sea with a red planet) is shown, with its colours moved to 101..204. A blue spaceship (17.asc, colours 205..255) flies along sine curves above the terrain. The only point light follows the ship.
  - The terrain rises from below in the first 5 s and sinks again after 54 s.
  - Fade in (blocking, background only), loop for 58 s of loop time, then a blocking fade out.
- **0000:0073 "THE END" (args: text = 'THE END', style = 2)**. The text is split at the first space into two lines. Each line becomes a 3D extruded-letter object (TText3D, 1117:20e8) with Gouraud shading from one moving point light. The palette is a black -> blue -> white gradient (style 2).
  - First 2 s: blocking fade-in over a black page, so nothing is visible.
  - Then 11 s: both words rotate about the X axis while the light sweeps across.
  - Then a blocking fade out.
  - A picture (item 36) is loaded and remapped, but the page is cleared right after that. **It never shows** (vestigial).
- **After 0073**:
  - main: 0d27:03ef (music fade out), 0d27:03cf (music stop), return.
  - 0000:a616: UnmaskIRQs, clearScreen, DS:2686 = 1.
  - Halt(0). Then the ExitProc chain reaches **0000:a370**, which calls **endScreen 0000:a2c1**. That shows the 80x25 text screen from resource item 42 (`res/42.bin`, 4000 bytes, char/attr pairs) and fades it in over 200 ticks.
- **No vsync anywhere in this slice**. Each frame draws into page 1, then `present()` copies 64000 bytes to A000:0000.
- Animation is **per frame**, not per tick: scroll speed and ship motion depend on the frame rate. Only the phase changes (rise/sink, light path, rotation) are tick-based.
- **Measured frame rate (7d84)**: about **28 distinct frames/s**. I counted 56 changes over 139 capture intervals at 70 Hz, video0008 frames 3341..3480 = demo time 575.0..577.0 s. The gaps alternate between 2 and 3 capture frames.
